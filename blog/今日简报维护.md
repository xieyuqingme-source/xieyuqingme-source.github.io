# 今天页维护

独立页面为「今天」`/today/`，英文 Today `/en/today/`，以「年 · 月 · 日 · 史」从一年走向此刻。页首显示北京时间日期与星期、农历节气、年进度和一句自动读数；随后依次为「年 这一年」「月 这个月」「日 此刻」「史 历史上的今天」、新闻、每日阅读。页内导航连接这六节。原「过去—今天—未来」静态装饰线由年进度线取代，按当前选定时刻占全年实际时长的比例绘制，并标出二分二至四个刻度；第几天、还剩几天仍按北京日历日计算。

「日」包含地球昼夜、日出日落、世界时钟、时间滑块和一行天气简读；地图、预设城市、城市搜索与详情收进默认折叠的「换个地方 · 天气详情」，打开时才初始化地图。「月」显示地月位置、月相和主要月相日期；「年」显示带二十四节气的公转图、太阳直射点曲线及相应读数。三张天文图共享同一时刻，按进入视口延迟绘制，支持明暗配色与减弱动态。历史条目增加「N年前」，每日阅读两张卡片只移动整节位置。

首页保持原五块和「今天」轻量入口，不请求天气；首页浏览器标签仍为「谢雨卿个人网站」，英文为「Xie Yuqing’s personal website」。今天页的新闻只显示最多3条，并提供「看世界」入口；完整汇集、往日存档与信息源目录由中文版 `/world/` 承担。天文计算、历史与两套名句仍独立维护。本文描述当前源码接口和维护方法，不表示新版已发布或远程工作流已验证。

## 天文计算与统一时刻

`astronomy-solar.js` 保留原太阳位置、昼夜与日出日落接口，新增月球低精度黄经、地月距离、日月角距、照亮比例和主要月相求解；原按平均朔望月命名的路径由这个单一月相来源取代。太阳几何沿用 [NOAA计算说明](https://gml.noaa.gov/grad/solcalc/calcdetails.html)，月球采用低精度三角级数和地平视差近似，再按日月黄经差求主要月相，并用下述USNO年历核对事件时刻。图为地理与时间的示意，不作为精密星历。

`astronomy-cycles.js` 从本地lunar-javascript读取节气和农历，与页首使用同一日历来源；节气日期与「N天后」按北京日历日计算。`home-earth.js` 提供共用时刻，拖动原地球卡片滑块时，地球、月相、月/年图、读数和年进度跟随同一snapshot；`home-today.js` 只负责文本与进度，`home-today-visuals.js` 只负责SVG。所选城市在南半球时，地面所见月相左右翻转；主要月相以事件所在的完整北京日历日命名，前后日回到相应象限名称。

地球公转轨道画成正圆，二十四节气每15°标一刻度，季节弧与直射点曲线表达一年中的位置；季节来自地轴倾斜，不能解释为离太阳远近。冬至、夏至、春分、秋分所在北京日使用当天文案，其余时刻显示下一回归线与下一次过赤道；这些日历日期继续由lunar-javascript提供。

天文fixture位于 `scripts/fixtures/today-astronomy/`，`sources.json` 保存2026年10月30日取得的官方响应地址、时间、SHA256与容差；原始JSON随测试保存。太阳对照2026—2030年20次二分二至，月相对照2026—2027年99次主要月相，测试容差分别为10分钟和60分钟。USNO的UT分钟读数在这一教育用途的分钟级检查中按UTC处理，不宣称证明其他年份或更高精度。

来源为 [USNO API说明](https://aa.usno.navy.mil/data/api.html)、[二分二至接口（2026示例）](https://aa.usno.navy.mil/api/seasons?year=2026)和[主要月相接口（2026示例）](https://aa.usno.navy.mil/api/moon/phases/date?date=2026-01-01&nump=50)。本地测试、普通构建和浏览今天页只读取随站保存的数据与计算代码，不自动请求NOAA或USNO；点击来源链接才会访问它们。

## 自动新闻

`home/brief/information-sources.json` 是信息源目录与采集共用的唯一活配置。当前59项目录、12个RSS/Atom候选中11个启用，均来自本轮获站主明确授权采用的预勾候选；不称站主逐项勾选，也不把未选条目说成站主偏好。Nature保留approved目录与候选但暂不采集。原 `news-sources.json` 的五源冻结为历史映射，兼容种子、旧Release与旧ID；合并配置保留15个已知来源身份（含停用Nature），实际只请求11个活ID。

活订阅为中新网要闻、联合国中文、BBC中文、BBC Top、Guardian International、纽约时报首页、半岛电视台、Economist World This Week、NASA News Releases、USGS Significant Earthquakes及Hacker News。保留原标题、来源、语种、原文链接和真实时间，只显示标题，不生成摘要或机器翻译。显示快照每源、每publisher最多2条，合计最多24条，按来源栏目顺序与四类轮取；今天页只取其中最多3条，完整汇集在 `/world/`。BBC两路共享publisher上限。Economist周刊头条归国际，不因媒体名称把政治头版归经济；未选经济专类feed时不另加来源凑齐类别。

这套规则是来源栏目选题与预设规则的组合，不是独立记者选稿，也不是全网重要性评分。严格按规范链接和规范标题去重；它不保证识别所有跨媒体改写的同一事件。不能因出现“大选”“加息”等词就给新闻加“重大”标签。后续增强应先有可核对的选题依据。

`published` 是原文发布时间，`collected_at` 是本站实际成功采集时间，二者不得混用。普通条目超过72小时退出显示；来源失效或没有合格条目时，可以少收或显示新闻源入口，不凑数、不刷新旧日期。

原始查询参数保留在读者跳转链接中。去重键仅忽略明确的跟踪参数，不可盲删 `id`、`dep` 等真正决定文章的参数。普通媒体条目只允许已配置的公开HTTPS域名；仅Hacker News显式允许安全公网HTTPS外链，表示社区票选链接，不能称为编辑部核过的标题，读者需回原站核实。订阅标题里的HTML转纯文本；采集器不抓文章全文，不在浏览器直接请求第三方新闻接口。

BBC中文订阅实际重定向到繁体，使用 `zh-Hant` 并保留繁体原题，不转简体。Nature于2026-10-31本机生产采集器核验时303跳转到idp.nature.com的身份cookie入口，被固定官方feed域规则拒绝，目录与feed的collect均为false；不跟认证域、不扩大白名单。先前观察到的RSS 1.0 RDF只有日级dc:date；若以后安全恢复采集，也不补造UTC零点或进入72小时今日池，仍按first_seen回退归档并标明无有效完整发布时间。UN订阅即使请求identity仍可能返回gzip：压缩输入与解压后内容各受1 MiB上限保护，不无限解压。

USGS Atom只有updated而无published，不把更新时刻伪作发表或地震发生时间；其feed继续启用以归档标题，按发布时间缺失的first_seen回退，不进入今日72小时池。

### 调度与持久化

- 北京时间08:20、14:20、20:20运行独立采集工作流。
- 采集成功后，以带时间及内容哈希的附件保存在固定 `news-data` GitHub Release；保留最近30份。
- 先上传并确认新附件，再清理旧附件；不覆盖唯一备份，不产生每天更新新闻的主分支源码提交。
- 采集工作流成功完成后，通过 `workflow_run` 触发现有 Pages 构建。
- 正常发布只在限时内读最后有效Release快照，不现场访问11个活新闻订阅。失败使用已校验种子，保留其真实时间；新闻过旧时显示来源入口，文章和照片仍可发布。
- `NEWS_SNAPSHOT_PATH` 可指向临时工作区的已校验快照；普通本地构建不联网。
- 工作流文件需存在于远程默认分支才会调度。可以在 Actions 手动运行 **Update news snapshot** 检查采集、Release 附件与后续发布；是否已启用、是否运行成功，以远程 Actions 记录为准。本机构建不执行远程存储或发布。
- GitHub定时任务可能延迟或丢失排队运行；公开仓库连续60天无活动可自动停用。不能保证 Release 附件变化算作重新激活的仓库活动。偶尔检查 Actions 状态。

### 新闻存档：采集记录与显示选择分开

同一次读取每个活feed，最多保留每源30条通过标题、链接和来源校验的条目进入独立capture；显示快照另按72小时、去重、每源/每媒体2条及最多24条规则选择，今天页再限3条。capture可以保留不进入显示的缺失、无效、未来或较旧发布时间条目；日文件写入时仍遵守冻结规则。存档只保存标题、链接、来源、时间与运行元数据，不保存文章正文、摘要、图片或读者数据。

目标为同一仓库的独立孤立分支 `news-archive`，路径 `archive/YYYY/MM/YYYY-MM-DD.json`；main继续维护网站源码。构建通过 `NEWS_ARCHIVE_PATH` 指定只读本地检出，未指定时使用 `.local-checks/news-archive`；CI发布前只读检出该数据分支，普通本地构建不自行拉取。校验通过后生成看世界往日日页、月历与标题索引，详情见[看世界维护](看世界维护.md)。每日文件为v1 JSON，包含 `date`、`timezone:"Asia/Shanghai"`、`items` 和 `runs`；每个item、run各占一行，条目按first_seen/ID、运行按collected_at/ID排序。capture上限512 KiB，单日文件上限1 MiB，全部输入与计划文件通过校验后才落盘；校验或大小失败不改已有存档。

| 层级 | 主要字段 |
| --- | --- |
| item身份与链接 | `id`、`title`、`url`、`canonical_url` |
| item来源 | `source_id`、`publisher`（稳定标识）、`source`（显示名）、`category`、`lang`、`origin` |
| item时间 | `published`、`first_seen`、`last_seen`、`archive_date`、`date_basis` |
| run核心 | 内容生成的`id`、`collected_at`、`origin`、`sources`、`displayed_ids`、`display_status` |
| 每源结果 | `source_id`、status（ok/failed/unknown）、received/archived/eligible、reason（安全异常类型或null） |
| run落盘结果 | writer生成的`archive_result:{stored_ids,frozen_ids}`，不改变原run.id；输入capture禁止提供这个结果 |

全部精确时间采用带秒的UTC ISO字符串，例如 `2026-10-30T15:59:01Z`。正常RSS条目按published的北京日期首次入桶；发布时间缺失、无效时published为null，未来时间则保留其真实UTC值。这三种回退分别标记 `first-seen-missing`、`first-seen-invalid`、`first-seen-future`，按first_seen的北京日期首次入桶。同一canonical ID入桶后保持原日期，不因后续来源修订标题或发布时间而迁桶，也不复制到别日。重复观测更新可写日期的last_seen，稳定元数据沿用最早观测与固定冲突顺序。

今天及此前3个北京日可补写；相差超过3日的日期冻结，不改其中条目或last_seen。迟到条目不能写入冻结日，也不挪到今天凑数。url保留读者跳转用的原链接，canonical_url复用现有去重规则，只忽略已审定的跟踪参数并规范query次序；ID继续为 `news-` 加canonical URL的SHA256前20个十六进制字符，不按标题跨媒体合并事件。

每次运行保存来源成败与received、eligible、archived计数。received是通过标题和链接校验的候选数；eligible是符合显示日期窗口、尚未套用显示数量与去重限制的候选数。**archived表示通过校验进入本次capture的数量，含义是captured，不等于实际写入每日文件的数量。** 实际接受与冻结拒绝分别看archive_result.stored_ids和frozen_ids；两组ID各自去重且不相交。例如一次capture有130条、实际接受122条并冻结拒绝8条时，不能写成永久保存了130条。received不得小于eligible或captured数量。

新显示快照的ID存为displayed_ids，必须是capture条目的子集。没有新显示快照时写 `displayed_ids=null`、`display_status=not-updated`，表示旧Release未更新，不伪称线上变为空列表。某次全源失败时仍可保存条目为空、来源真实失败的运行记录；只记录安全异常类型，不保存上游响应正文。这些ID记录生成的显示快照，不是Pages部署成功的审计。

#### 旧资料与手动导入

首次成功归档且尚无legacy导入标记时，自动导入两份2026年10月26日、27日旧手工样刊；独立手工条目标 `origin=legacy-manual`、`date_basis=legacy-edition`，按edition_date分桶。这是手工资料的明确例外：它们的编辑双语标题不冒充RSS原文；无精确时间者published为null，原日期字符串、旧ID与双语标题保存在legacy.entries中，首次导入的first_seen/last_seen为实际导入UTC。旧摘要、priority/major标签不导入。10月26日六项中的两项共用同一文章链接，归成五个canonical item并保留六条旧标题/ID；10月27日为六项。旧business/culture类别只用于legacy-manual，不增加实时来源或类别。

`legacy:{edition_date,entries}`是旧人工样刊旁证，与主条目的来源身份分开。同canonical条目合并时，主origin、原标题、来源与首桶规则照旧；即使更早的RSS或Release记录成为主条目，所有合法legacy注记仍去重保留，不把主origin改为legacy-manual。跨样刊日期的entry可另带edition_date；未带时沿用legacy.edition_date，兼容原单刊格式。每日持久化item可在rss/release-import主来源下携此旁证，但RSS/Release的capture输入仍禁止提供legacy，手工capture也不能伪装成writer生成的跨刊合并结果。冻结规则不变。

此次待补导入的旧Release只能恢复仍保留附件中当时保存的最多8条，不能还原此前未保存的完整feed；后续附件也只能按其真实内容恢复。条目标 `origin=release-import`；当年每源采集结果不可考，所以status为unknown，received/eligible为null，不伪造成功条数。导入前验证附件大小、名称时间、内容哈希与v1快照schema。历史bootstrap只创建缺失冻结文件，不改已有冻结文件。

上线后需要导入时，由维护者手动执行：

1. 确认新工作流已位于远程main，在Actions选择 **Update news snapshot → Run workflow**，分支main，将 `import_release_snapshots` 设为true，运行一次。
2. 查看 **Archive all validated headlines and true source outcomes** 步骤，确认实际完成；再检查news-archive中的每日JSON与archive-meta.json，区分legacy-manual和release-import。
3. 当次有合格新闻时，确认 **Store a new validated snapshot before pruning old data** 完成。若当次采集全失败，这一步跳过、旧Release不变，但此前存档步骤仍可能已完成历史导入，应逐步核对。
4. 后续定时或普通手动运行保留输入默认false，不必每次重复历史导入。手动导入失败时先查失败记录，不能把失败写成已导入。

#### 发布门禁与失败隔离

远程写入只允许受信任仓库main分支的采集Actions入口，沿用contents: write权限。归档写入器在临时独立仓库创建或读取孤立news-archive分支，只允许存档数据；正常push，拒绝后重新fetch、按ID合并，最多3次，不force。Pages只读存档检出；普通构建、浏览器、离线merge与校验不写GitHub。

capture生成、校验、序列化或本地写入的预期校验/IO错误与显示快照隔离：stderr安全告警，仍保存通过校验的显示快照。只有新capture校验、写入成功，采集步骤才向自己的GITHUB_OUTPUT设置 `archive_capture_ready=true`；后续归档必须取得这个本次成功标识，不能因为残留旧capture就当作成功，不靠mtime判断，也不在失败时删除旧文件。

正常归档步骤失败会在Actions留下失败步骤，continue-on-error保留既有Release→Pages通道，因此总体绿色不保证归档完整，须查看归档步骤。显式手动历史导入缺有效capture或导入失败时会硬失败，停止后续Release更新/清理，保护待导入附件。多文件merge在全部校验后逐个原子替换，不宣称磁盘IO中断时有跨文件事务保证；远程提交只在整个临时仓库合并完成后进行。

本轮核实了12个官方订阅及官网入口，完整状态见来源审核说明；本地测试使用网络、git/gh替身，不作为远程权限、分支规则、真实推送重试、历史下载或部署成功的证据。新版看世界的日页、月历与检索属于当前源码功能，是否已经上线、存档是否已检出，须在发布后按实际页面和Actions记录确认。

## 保留的历法、天气和地图行为

日历与历史日期统一北京时间；天气和地球使用读者主动选择的城市或地图坐标。「日」节先显示地点、温度、天气、体感的一行简读；「换个地方 · 天气详情」默认收起，展开时才初始化地图，预设城市、搜索与原详情保留。天气地图加载本站Natural Earth数据，可点选、拖动、缩放，也可用方向键移动、Enter选择；拖动不会同时选点。任意坐标显示为地图选点，不臆造最近城市名称；取得有效天气与时区后才替换当前地点，失败保留原天气。

城市搜索把输入的城市名发送到 Open-Meteo 地名服务；地图选点把经纬度发送到其天气接口，并使用返回的时区。页面不读取设备定位，仅在浏览器保存所选城市或坐标与最近一次天气。17个预设、天气缓存、29种WMO提示、体感温度/湿度/风速/风向/海平面气压继续保留；首页轻量入口不请求天气或地名服务。

地球保留昼夜、日出日落、六时钟、时间滑块和减弱动态支持，月相统一放入「月」节并使用同一计算来源。固定北京、吉隆坡、伦敦、纽约、莫斯科；自选城市不在其中时排第一，否则迪拜排第六。

`knowledge.json`、`memes.json`和旧`news/YYYY-MM-DD.json`仍作为既有公开资料保留校验，今天页不显示小知识或热梗卡片，也不用人工v2文件作为实时新闻来源。两份旧样刊另以legacy-manual导入存档，往日日页明确标为旧人工样刊，不把固定日期样刊当作最新一期。发布测试验证结构与规则，不锁定某一天的新闻标题、语录或历史事实。
