# 今日简报维护

完整简报位于 `/today/`（英文 `/en/today/`），由公开数据文件构建，显示 `home/brief/news/` 中日期最新的一份。首页只显示日期、节气、黄历和小地球，链接到完整简报；首页不请求天气，也不读写天气缓存。新闻由人工挑选，标题和摘要依据原文；点「阅读原文」看全文。本轮没有新闻自动抓取或定时任务。页面运行时不请求 CDN；天气沿用 Open-Meteo。

## 数据文件

| 文件 | 字段与用途 |
| --- | --- |
| `home/brief/news/YYYY-MM-DD.json` | 每日新闻。顶层只有 `version`、`edition_date`、`updated_at`、`status`、`items`；版本为 `2`，状态为 `manual` 或 `auto`。日期与文件名一致，更新时间使用同一天的北京时间 `+08:00`。 |
| `home/brief/knowledge.json` | `version: 1` 与 `items`。每条含 `id`、双语 `title` 与 `text`、`source`、`url`，可选 `trigger`。 |
| `home/brief/memes.json` | `version: 1` 与 `items`。每条含 `id`、`term`、双语 `meaning`、`source`、`url`、`added`。 |
| `home/brief/rules.json` | `version: 1` 与 `weather`。每条含 `id`、`field`、`operator`、`threshold`、双语 `text`。 |
| `home/brief/holidays/YYYY.json` | holiday-cn 的原始年度数据，保留 `$schema`、`$id`、`year`、`papers`、`days`；同目录附 `LICENSE`。 |
| `home/daily-content.json` | 只保留 `version: 1` 与 `quotes`。每条名言含 `id`、双语 `text`、`author`、`work`、`translation_note` 和 `url`。 |

所有文件都是 UTF-8。维护已有文件时保持其原有换行方式。只修改来源文件，不直接编辑 `_site_unified/`。

### 每日新闻

每条新闻有以下字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 本文件内唯一的小写字母、数字和连字符编号。 |
| `category` | `domestic`（时政）、`world`（国际）、`economy`（经济）、`science`（科技）、`culture`（文化）。 |
| `title`、`summary`、`source` | 均为 `{"zh-CN": "中文", "en": "English"}`。中文摘要不超过 60 字。 |
| `published` | 原文发布时间，ISO 日期或含时区的日期时间，不晚于 `edition_date`。 |
| `url` | 原文的公开 HTTPS 链接。 |
| `priority` | `normal` 或 `major`。 |
| `major_reason` | 可选的双语说明；`major` 时必填。 |

平时每个板块一条，共 5 条；同一板块增加的条目需标为 `major` 并说明原因，总数在 1 到 12 条之间。没有合适新闻的板块就空着，不用旧闻凑数。`major` 排在前面，其余依次为时政、国际、经济、科技、文化。

中文摘要按非空白字符计数，空格等排版空白不计入 60 字；这使本次提供的原始摘要得以逐字保留。中文每日小知识同样按非空白字符计数，不超过 120 字。英文仍执行公开文本长度上限。

迁移兼容：`2026-10-26.json` 原样保留为历史 version 1 样刊，其中有两条未核实日期，不补造时间。只有这一个文件、且它不是最新文件时可走历史校验；完整简报最新一份和其他日期均必须使用 version 2。不要复制旧样刊作为新一天的数据。

### 每日小知识

`trigger` 可为 `{"solar_term": "霜降"}`，在该节气期间优先显示；也可为 `{"date": "MM-DD"}`，每年这一天优先显示。没有匹配项时按北京时间日期轮换。来源名称和来源链接必填，新增条目必须有可靠依据。

### 热梗

`term` 可使用纯文本；迁移条目保留原有的双语标题对象。`origin`、`example`、`why_popular` 是可选双语字段，留空时不显示对应行。相关链接需同时填写 `related_url` 和双语 `related_label`。来源 `source` 与 `url` 应是一篇主流媒体的解读报道；`added` 是实际收录日期。只显示最近收录的一条；条目数组为空时不显示热梗卡片，另外三张卡按自然高度排列。

**热梗红线：不收侮辱群体或地域的、低俗的、涉及真人隐私的、来源不明的、政治敏感的梗。** 没有新的合适热梗就不动，不按固定周期凑数。

### 天气、历法与假日

天气规则复用现有 Open-Meteo 返回值，不增加天气请求：

| `field` | `operator` / `threshold` | 提示 |
| --- | --- | --- |
| `precipitation_probability_max` | `gte` / `60` | 可能下雨，记得带伞 |
| `temperature_2m_max` | `gte` / `33` | 很热，注意防暑 |
| `temperature_2m_min` | `lte` / `0` | 很冷，注意保暖 |

三条都不满足时不显示提示。`gte` 表示大于等于，`lte` 表示小于等于。

农历、干支、生肖、节气和黄历使用本地 `home/assets/vendor/lunar-javascript-1.7.7.js`，许可证同目录；首页在页面 load 之后的空闲时间加载，`/today/` 直接加载。黄历标明「传统民俗，仅供一乐」和「据 lunar-javascript 推算」。法定假日与调休读取 holiday-cn 的公开年度文件，不手写或编造数据；年度文件必须有官方依据 `papers`、非空 `days`，每个日期属于文件所写年份。尚未公布的空年度文件不加入。

## 校验与过期规则

构建在写入输出前检查全部日期新闻和其他简报数据。缺字段、额外私有字段、错误类型、重复编号、不合法日期或分类、超长文字、本机路径、控制字符、私人网络链接、含凭据或查询令牌的链接都会使构建失败。正文纯文本由构建器转义，不在数据中放 HTML。

- `edition_date` 比今天（北京时间）早 1 天，显示「昨日要闻」。
- 早 3 天以上，要闻区只显示「新闻暂停更新，先看看地球」。

完整简报没有收起按钮，新闻、今日、此刻地球和底部四张卡均按自然高度排列，不设置内部滚动条。旧文一句继续使用 `home/home-picks.json` 的 quotes 与 `home-now.js` 每日轮换；featured 数据仍校验，暂时不显示。

## 每日更新

1. **确认日期**：确认今天的北京时间日期。`home/brief/news/` 里已有今天的文件时，就在它的基础上更新。
2. **五家媒体各找一条**：看指定栏目里最靠前的一条。新华社、联合早报、第一财经取 36 小时内的，Nature、界面文化取 72 小时内的。

   | 板块 | 媒体 | 栏目 |
   | --- | --- | --- |
   | 时政 | 新华社 | https://www.news.cn/politics/ |
   | 国际 | 联合早报 | https://www.zaobao.com.sg 的国际即时新闻 |
   | 经济 | 第一财经 | https://www.yicai.com/ |
   | 科技 | Nature | https://www.nature.com/nature/articles 里类型为 News 的条目 |
   | 文化 | 界面文化 | https://m.jiemian.com/lists/130_1.html |

3. **重要消息**：过去 36 小时内有下列事件时，可以超过 5 条，最多 12 条。这些条目标为 `major`，写清原因。
   - 重要国家的大选结果或政权更替；
   - 外国元首访华，或中国领导人出访；
   - 造成重大伤亡的灾害或事故；
   - 主要经济体央行的利率决议；
   - 中央或国务院的重要政策文件；
   - 重大科学发现。

   没有合适新闻的板块就空着，不用旧闻凑数。
4. **核对**：
   - 每条都要打开原文，照抄原标题、发布时间和链接。
   - 摘要不超过 60 字，只陈述事实，不评论。
   - 同时写英文标题和摘要；外文媒体用原题。
   - 不确定的信息不写。
5. **热梗**：搜索最近 7 天主流媒体（新华网、人民网、澎湃、界面文化、中国青年报等）对网络流行语的解读报道。有符合红线要求的新梗就加进 `home/brief/memes.json`，没有就不动。
6. **每日小知识**：今天是节气首日或重要节日，而 `home/brief/knowledge.json` 里还没有对应条目时，补一条并附可靠来源；否则不动。
7. **写入**：写 `home/brief/news/YYYY-MM-DD.json`。`edition_date` 为今天，`updated_at` 为当前北京时间，`status` 为 `manual`。
8. **检查**：运行以下两条命令，以及 `pages.yml` 里与简报相关的测试：
   - `python scripts/build_site.py --site-url https://xieyuqing.me`
   - `python scripts/check_site.py --site-url https://xieyuqing.me`
9. **收尾**：不 commit，不 push。最后列出今天收录的条目（标题、来源、时间）和改动的文件，由用户在 GitHub Desktop 里提交。
10. **打不开的媒体**：某家媒体打不开就跳过，在汇报里说明。
11. **校验失败**：数据校验不通过就修数据，不要改校验规则和测试。
