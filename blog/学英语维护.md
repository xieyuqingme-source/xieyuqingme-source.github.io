## 卡片清单与正文

清单顶层必须恰有`version`、`columns`、`cards`，版本为1。五个栏目ID固定为`words`、`classics`、`between`、`myths`、`mistakes`；每个栏目提供`id`、`title`、`english`、`description`。

每张卡片的共同必填字段：

| 字段 | 含义与约束 |
| --- | --- |
| `slug` | 2–64个小写英文字母、数字或连字符，以字母开头，唯一；`tools`、`play`、`quotes`、`map`保留给栏目工具路径 |
| `column` | 上述五类之一 |
| `title`、`summary` | 公开纯文本，分别不超过120字符；summary是直接给答案的30秒版，不能写成截断摘要 |
| `level` | 整数1、2、3，分别为入门、进阶、挑战 |
| `tags` | 1–6个短标签，每个不超过24字符 |
| `sources` | 来源对象列表，字段恰为`label`、`url`、`checked_on`；每卡至少1项，考据至少2项，最多12项；核对日期为`YYYY-MM-DD` |
| `related` | 最多6个项目；填写另一张已发布卡片的slug，或以`/articles/`开头的实际原文章路径（如`/articles/文章名.html`），不填尚未生成的页面 |
| `added` | 加入日期，`YYYY-MM-DD` |
| `status` | `published`或`draft`；只有published生成页面。draft同样接受字段、正文与来源检查，不能拿它隐藏坏数据 |
| `ai_assisted` | 布尔值，如实说明初稿和例句是否有AI辅助；不能为省略说明而写false |

来源URL必须是安全的公开HTTPS地址，无凭据、私网地址、控制字符或本机路径。清单不接受未知字段。构建只读取清单明确列出的`cards/<slug>.md`；目录符号链接和指向仓库外的路径会被拒绝。

正文从H2开始，不另写H1；H1由清单标题生成。各类必需的小节都应有正文，同名小节不能重复，代码围栏里的假标题不算小节。

| 栏目 | 必需H2 | 专有元数据 |
| --- | --- | --- |
| 词的身世 | `故事`、`可以这样用` | 必填`headword`；可选`journey`，每站恰为`language`、`form`、`period`、`place_zh`、`lon`、`lat`、`approximate:true`，不确定的时间留空，不编贸易路线 |
| 经典一页 | `导读`、`原文`、`可以这样用` | 必填下述`work` |
| 中英之间 | `对照`、`为什么`、`可以这样用` | 不填写其他类别的专有字段 |
| 考据 | `流行说法`、`证据`、`结论` | 必填`verdict`，值为真、假、存疑、部分正确 |
| 别说错 | `错句`、`对句`、`为什么` | 来源由清单统一渲染成第四段`来源`，不在Markdown重复录入 |

允许补充有内容的新H2，但不要删必需小节。Markdown使用markdown-it渲染，关闭原始HTML；引用只用公版原文。渲染器在「可以这样用」小节开头统一加一次「例句为编写的示例」，正文不要再逐条重复标签。公开标签写「和中国有关」，不用选题过程中的内部术语；先说具体例子，再给必要解释，不重复编辑流程或作者经历。词的身世与中英之间建议300–700字，考据300–800字，经典导读200–400字。正文自然展开，不在卡片内裁切或滚动。

首页无脚本时按五类完整显示，栏目介绍链接跳到相应小标题；有脚本时支持栏目和难度筛选，写进`column`、`level`查询参数，并通过详情面包屑保留返回状态。不使用持久存储保存筛选，不添加联网搜索。

当前40张卡片：词的身世12、经典一页8、中英之间7、考据5、别说错8。新增内容逐条核对见`english-corner/CONTENT_REVIEW_V2.md`。错句和对句为编写的情境示例，统一在错句段说明一次；不要把在其他语境中正确的表达说成永远错误。

## 经典原文、公版与难词

`work`必填字段为`author_zh`、`author_en`、`title_zh`、`title_en`、`first_published`、`author_died`、`range`、`edition`、`edition_url`、`excerpt_words`、`excerpt_sha256_lf`。作者、作品、选段起止和具体版本分开记录；电子书上线日期不等于原作出版日期，创作日期也不等于出版日期。遇到版本节录本，应明确说明范围，不能称为原信全文。

按构建时北京时间年份Y检查：`first_published ≤ Y−96`且`author_died ≤ Y−51`；2026年的门槛分别为1930、1975。这是本栏目的保守筛选规则。只引用原作正文，不取现代编者导言、注释或受保护的现代译文；歌词一句不收。年份应有具体版本或可靠机构资料支持，不能仅填一个恰好过关的年份。

原文放在`## 原文`，不超过600个英文词。构建从解析后的该小节取得内容，把CRLF和单独CR换成LF，再去掉小节首尾空白；其余内部字符、标点、空格和换行均保留。`excerpt_sha256_lf`是这些UTF-8字节的SHA-256。计词使用`[A-Za-z]+(?:[’'-][A-Za-z]+)*`，与`split()`口径不同。修改原文后应回原版重新核对，再同步词数和指纹，不能只为让测试通过而重算。

可以在仓库根目录运行下列离线片段检查已有卡片的取值：

```python
import sys
from pathlib import Path
sys.path.insert(0, "scripts")
from english_corner import sections, text_hash, word_count

body = Path("english-corner/cards/keller-water.md").read_text(encoding="utf-8")
original = sections(body)["原文"]
print(word_count(original), text_hash(original))
```

`notes.json`格式为`{"version":1,"works":{"<slug>":[...]}}`。每篇经典必须有3–6项；每项字段为`term`、`meaning`、`source_url`、`source_label`、`checked_on`。term必须实际出现在该篇原文中，且同篇不能重复；meaning是结合上下文整理的中文含义，来源应是读过的公开词典。不要直接复制整段现代词典定义。

经典原文中的已核难词使用虚线标记，轻触、点击、键盘聚焦均可打开释义，Esc关闭。词表保留为原生details，关闭JavaScript后也可展开阅读。共享的`scripts/reading_annotations.py`只在Markdown的text token中标记一次精确出现，保持原字符与公版哈希；文选和学习使用同一算法和`reading-annotations.js/.css`浮层机制。文选原复制、显式搜索和双语行为保留。

## 英语名句的三份资料

`english-quotes.json`顶层为`version:1`及`quotes`数组。每条共同字段：`id`、`text`、`translation`、`translation_source`、`author_zh`、`author_en`、`work_zh`、`work_en`、`locator_zh`、`first_published`、`author_died`、`url`、`note`；可选`related`须指向已发布的`/english/<slug>/`。未知字段、重复ID、忽略标点与大小写后重复的原句都会拒绝。

- 英文原句同时不超过45词和300字符，中文译文不超过120字符，知识说明note不超过160字符。
- 原句和公版日期规则同经典。来源链接指向实际原文，不把名言搜索页当出处。
- 优先引用完整句子。中途截取须在对应边界加「…」，不得擅改原作首字母；首字符为大写字母、引号或省略号，末尾为句末标点、引号或省略号。诗句保留经原版核对的换行，至多四个非空诗行；中文译文同样可换行。Python和JS同时检查，服务器用`br`、轮换后用`white-space:pre-line`保留行分隔。`locator_zh`只写章、幕、节或说话人等位置，不用处理过程描述。
- `translation_source:{"type":"site"}`会在引文说明中显示“中文为本站译文（AI辅助，逐句核对意思）”。
- 使用公版出版中译时，填写`{"type":"published","name":"译本及译者","url":"https://…","translator_died":年份}`；译者去世年也必须满足Y−51。还要人工核定所引译本本身的出版时间与可用范围，不能只靠译者卒年就复制后来出版的文字。现有schema没有单列译本出版年，字段检查不替代这一步；本批全部使用site类型。不得复制仍受保护的现代译本。
- 两种今天页读取完全相同的英文原句、中文译文、作者作品、说明和相关链接；只有标题、按钮及栏目入口文字跟随页面语言。正文分别用`lang="en"`、`lang="zh-CN"`标注。

`english-quotes-review.json`也使用`version:1`及`quotes`。每条必须有`id`、`text_sha256_lf`、`source_url`、`locator`、`checked_on`、`method`、`source_sha256_lf`、`misattribution_check`、`public_domain`，可选`bibliography_urls`、`source_text`、`display_note`。后两项记录未经边界省略号处理的实际字句和分行/截取说明，构建检查显示只能增补边界省略号与诗行空白，不能改写来源字词。这些核查记录不注入页面。

其中`public_domain`恰含`first_published`、`author_died`、`basis`。每个展示ID要对应恰好一条核查记录，原句LF指纹、来源URL、出版与卒年必须一致。原句指纹不额外去掉首尾字符；不要套用经典小节的strip步骤。来源页指纹应从当次真正核对的源文件生成，并注明核查方法和定位。离线检查能发现正文与记录不一致，不能代替重新阅读原文，也不会联网证明远程页面未变。

`english-quotes-sources.md`是公开逐条通读索引，记录原句、译文、位置、语境、来源和翻译身份。修改名句后同步三份文件；新增数量与作者分布从当前数据统计，不在代码中硬编码每日句子。当前200条、32位作者，每位作者不超过12条，按作者交错排列；发表时间、人物台词与反讽语境都要留有依据。

两张阅读卡片分别有独立牌组和按钮。北京时间日期决定首句，先遍历完整池再洗牌，轮次交界不立即重复。60秒检查仅在跨日时重置，不覆盖读者手动选择；中英切换用一次性内存交接保留两套当前句和剩余顺序，普通离开后返回重新按日期开始。名句不使用localStorage或sessionStorage，离页时清理监听与计时器。无JavaScript时仍有构建当天的两张完整卡片，换句按钮隐藏。

年份字段内部继续叫`first_published`以兼容既有校验；具体记录可能采用所引的早期修订版或节录本年份。因此公开页面写“作品/所引版本”，不用“首刊”概括所有记录。它不是电子书上线日期，仍须满足公版门槛。

## 小测验与名句库

名句库由同一份已核名句数据直接渲染，不另维护副本。服务器输出完整原句、译文、作者作品、作品或所引版本年份、出处和折叠短注，每条稳定锚点为`quote-<名句ID>`；诗行用`br`保留。作者与作品/版本时期联合筛选写入`author`、`period`查询参数，不保存个人数据。没有JavaScript时完整列表仍可读。今天页引文说明、小测验答案与英语首页均有入口。

`quiz.json`为`version:1/questions`，只维护知识题，每题恰有`id`、`mode`、`text`、`choices`、`answer`、`explanation`、`card`、`sources`。mode为`etymology`或`origins`，四个选项须唯一、答案须属于选项；卡片须已发布，每个来源URL须属于该卡片已经核对的来源。不要把争议路径写成唯一词源。题源逐条说明见`english-corner/QUIZ_SOURCES.md`。

作者题由`english_quiz.build_quiz_pools()`从同一名句库派生，按作者卒年选择距离最近的其他作者为干扰项，近似同一时代；不把后来选集或修订版的出版年份当作作者时代；不会编造作家。输入知识题可为空以支持最小测试夹具，但生产清单测试要求两知识模式各至少10题。目前各12题。前端每轮10题，作者模式优先10位不同作者；随机数可注入测试。答题后显示解释、来源和阅读链接，保留错题回顾，不计时、不存分、不设排行榜。无脚本时显示卡片与名句库链接。所有监听由PageScope清理。

名句、题干与解释通过文本节点展示；JSON脚本用统一安全转义，不注入引文核查记录。公开题干与解释如实标注编写及AI辅助。三份名句资料仍按上节统一核对。

## 单词地图

`/english/map/`完全从已核词卡journey派生，当前10条。代表坐标与来源见`english-corner/MAP_SOURCES.md`；坐标不能反推实际路线或日期。未知时期保持空，long time no see只画一个点，serendipity为故事关联，ketchup保留可能中介。JSON安全转义，服务器输出全部路线作为无JS/失败备用。地图本地D3在页面head先于地图模块加载，SPA每次重新执行；只调用三种纯几何函数，SVG和监听使用原生API。没有持续动画，不用滚轮抢页面滚动；手机纵向意图不捕获，多指手势交还浏览器。所有监听、观察器和底图请求离页销毁。

## 数字工具与资源接入

首页「玩一会儿」连接既有排行工具，选择「名著排行」后使用独立的`template:book`草稿。20本英文原著的默认五档只是阅读体验的娱乐示例。配图由imagegen逐张生成并目视检查，使用`home/assets/books/`内640×640的本地WebP；书目与提示词摘要见该目录`SOURCES.md`。总览拼图保存在本地证据目录，不发布。中文、英文名称和场景alt在`ranking-model.js`的`BOOK_ART`及`home/locales/games.json`中；修改名称不迁移或覆盖用户自定义内容。

书图的固定20文件元组为`scripts/game_assets.py`的`GAME_BOOK_ASSETS`，由`build_site.py`导入并在任何输出写入前预检；同时作为学习Markdown图片的白名单，避免两处名单漂移。不扫描图片目录，不发布其中说明或预览；缺图、链接目录、错误格式或非方形图片都会失败。学习正文只能使用该白名单中的本地WebP且必须写alt，外链图片、任意路径与查询参数继续拒绝。

数字转换用BigInt定点运算，保留4位输入小数；支持阿拉伯数字、正确三位分节的逗号/空格、全角数字和标点、数字加十百千万亿、按单位从大到小的复合写法，以及不区分大小写的thousand/million/billion/trillion和a million。第一版不识别纯汉字数词，不支持含义不统一的“兆”。

范围为0至小于10¹⁶。输出带单位标签的三位/四位分组、中文简写与整数读法、英文简写及小于10¹⁵整数的英文全拼；每组为真实DOM文字，窄屏可换行。中文非整单位用「1234万5678」这样的混合写法，另给「约1235万」，整单位仍为「14亿」。英文简写最多两位小数，发生近似时显示≈；四位分节明确为演示。现代英文全拼采用美式不加and，页面另说明英式习惯。无脚本时保留静态单位对照表。

九个学习CSS/JS资源通过`english_corner.py`复制，由`version_shared_assets()`的资产名单及正则同时登记版本号，在模板中本地加载。页面脚本受现有PageScope包装，并登记离页清理。不要编辑`_site_unified/`的生成文件，也不要在运行时下载词典、Gutenberg正文、字体或CDN脚本。

## 朗读与数字练习

经典原文、12张词卡的词头和200条名句库条目提供可选小朗读按钮；只在学英语加载`english-speech.js`，今天页不加。仅选`localService:true`的英语语音，优先en-GB、再en-US及其他本地en；没有可用语音时按钮和设备说明隐藏。点击同一按钮停止，换目标先取消，离页取消；不回落到云端默认语音，不发送文字到API。

数字「练一练」有中文→英文与英文→中文两模式，以本地16个教学数值出题，一轮不重复，题值不代表真实人口或统计。复用BigInt精确判分；练习要求目标语言单位（英文thousand/million/billion/trillion、中文万/亿），裸数字只提示换单位。普通转换器继续接受裸数字。键盘Enter尊重IME，答案与成绩均不保存，离页统一清理监听。数值分组的标签是真实DOM文字，手机可换行。

## 新增、修改与退出的步骤

1. 先确认选题适合中文读者，读具体来源，核清事实与公版边界。无法确认的候选先退出，必要时以“存疑”说明有文献支持的分歧，不能用它掩盖完全没有来源。
2. 卡片先写公众版Markdown，再登记清单、来源、相关链接；经典同时补work和难词。名句先核原文与译意，再更新三件套。自编例句、本站译文和AI辅助必须如实标注。
3. 删卡片时，同步清理其他卡片的related、名句related及notes；不保留指向已退出页面的入口。改变slug会改变公开地址，应优先保留已有稳定slug。
4. 跑以下检查和整站构建。生成目录由构建器管理；退出路由后确认sitemap和生成页面清理结果，不手工篡改输出。
5. 内容与工程验证都通过后，站主再用GitHub Desktop审阅与提交；本轮开发过程不自动提交或部署。
