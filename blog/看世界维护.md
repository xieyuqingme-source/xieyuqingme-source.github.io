# 看世界维护

本文说明当前源码的接口与维护方法。新版的远程部署、存档检出、定时调度与历史导入仍须在发布后按真实结果确认，不能用本地测试代替远程验证。

「看世界」仅做中文版，提供今日来源标题、往日存档和一手优先的信息源目录；标题保留原文语言，不为英文标题自动生成中文摘要。今天页仍有中英文版，顺序为「年→月→日→史→新闻→阅读」，通过页内导航跳转，新闻只保留最多3条和看世界入口。天文、历史资料与两套阅读引文的维护见[今天页维护](今日简报维护.md)。

## 名单、采集与选取

当前公开59个目录条目、12个订阅候选中11个启用，属于55条预勾网格与12个预勾RSS候选的并集：重复机构合并，另增加4个仅在RSS候选中的机构。Nature保留目录但暂不采集。一个目录条目可以有多个官方入口或订阅。最初的勾选来自Claude初稿；本轮站主明确授权按预勾项做第一版、核验不合格先不启用，不代表站主逐项勾选或私人常看偏好。未选条目不发布。

目录条目包含领域、类型、网址、语言、地区、推荐理由、访问提示、最后核对日期、`status`、`collect`、`official_links`和`feeds`。只有approved目录中的approved且collect为true的feed参与活采集；目录的collect标签必须与其feed一致。获授权但暂时无法采集的订阅可以保留在目录，collect为false并记录实际原因，不能因一次403就自动删除。

活订阅由新canonical文件派生，当前为11个ID；全部approved候选及不重名的旧ID映射共同保留15个已知来源身份。`un-news-zh`、`nasa-releases`沿用旧身份；`bbc-world`、`guardian-business`、`chinanews-china`只为旧快照兼容，不被当作活源请求。停用的Nature仍可验证已有快照，但collect_ids不含它，不参与fetch。旧五源文件不可与新目录双重维护。

显示选择按国内、国际、经济、科技四类轮取，每源最多2条、每publisher最多2条，总计最多24条。BBC两路共用publisher上限。只收具有精确原文发布时间、且时间位于采集/显示时刻此前72小时内的条目，不把collected_at当作published，不把未来时间放进今日池。看世界静态页在构建时再次过滤；今天页仅显示其中最多3条。数量不足时如实少收；没有经济专类候选就不擅自加源，也不把政治头版移进经济栏。

这些是来源编辑选题与预设轮取规则的汇集，不作全网重要性排名。只保存和显示标题、链接、来源与时间，不抓文章全文，不调用付费API，不机器翻译新闻。

| 特殊订阅 | 必须保留的边界 |
| --- | --- |
| BBC中文 | 官方地址重定向到繁体订阅，lang为`zh-Hant`，保留繁体原题；不是自动转简体后的版本 |
| Nature（暂不采集） | 2026-10-31本机生产采集器遇303身份cookie跳转至idp.nature.com/authorize，固定官方feed域规则拒绝；目录/feed均collect=false，不跟认证域、不放宽白名单。先前RDF只有日级dc:date；若以后安全恢复，也不补造精确published或进入今日72小时池，按first_seen回退归档 |
| 联合国中文 | 响应可能是gzip；压缩输入与解压后内容各有1 MiB上限，解析先受限解压 |
| USGS显著地震 | Atom只有updated而无published；不把更新时刻当作发表或地震发生时间。feed保持启用以归档，按发布时间缺失的first_seen回退，不进今日72小时池 |
| Hacker News | 社区票选原站链接，唯一显式使用`link_policy: public-https`的feed；只放行安全公网HTTPS原链接，不误称编辑部已核实其标题，不抓外链网页 |
| Economist周刊头条 | 按world分类，不能仅因媒体名称就把国际政治头版归入经济 |

其他媒体条目使用已审定的publisher域名白名单。原链接保留真正决定文章的查询参数；canonical去重只移除已明确的跟踪参数。官网访问受限、付费全文、登录要求、验证页与地区访问差异写在每项access及审核说明中；2xx订阅响应不等于原文全文免费或所有地区都能访问。

## 存档输入与真实空白

原始存档在独立`news-archive`分支，数据根目录内为`archive/YYYY/MM/YYYY-MM-DD.json`。构建读取环境变量`NEWS_ARCHIVE_PATH`指定的本地根目录；未指定时使用仓库内被忽略的`.local-checks/news-archive`。它应指向含archive子目录的根，不能指向单日日文件、一个Release快照或来源清单。

CI发布入口只读检出存档分支后供构建读取；存档不可用时允许站点其余部分继续构建。普通本地构建不会自行发现、拉取或写入远程分支，也不自动联网补历史。缺失、不可读、路径不安全、schema错误或日期与路径不符时显示「存档暂不可用」，不暴露本机路径或半份索引。

三种状态必须区分：

- 没有该日文件：未存档，不能推断当天没有新闻或采集失败。
- 有合法日文件但items为空：确有空存档；运行记录可以说明失败或其它情况。
- 有标题但仅来自旧人工样刊或Release导入：说明真实来源，不能冒充当日自动采集成功。

当日文件保留全部通过存档规则的条目，不受今日24条上限限制；每次采集capture仍最多每源30条。只保存标题、原链接、来源、时间与运行元数据，不保存正文、摘要、图片或读者资料。单日文件上限1 MiB；capture上限512 KiB。

正常RSS按原文发布时间的北京日期入桶；缺失、无效或未来时间按first_seen的北京日期回退，分别标记原因。同canonical ID首次入桶后不跨日复制或迁桶。今天及此前3个北京日可以补写，超过3日冻结，不把迟到条目挪到今天凑数。日页展示条目origin、date_basis、首次/末次观测，并区分生成快照的displayed_ids与实际落盘结果；这不是Pages部署审计。详细schema与合并规则见[今天页维护](今日简报维护.md)。

月历的「—」表示缺少日文件，「0」表示存在合法日文件但无标题。最近7日只取真实北京日窗口，不用更老日期补满。一年前的今天只在对应日期确有标题时出现；2月29日没有合法对应日期时不借2月28日或3月1日代替。

日页的前一天/后一天只连接实际存在的相邻日文件；缺日不链接，可回月历选择其他日期。旧人工样刊标`legacy-manual`，保留旧双语标题旁证；旧Release标`release-import`，只能恢复附件当时保存的标题，无法还原未保存的完整feed。当前快照或种子只供今日汇集回退，不能用来制造往日文件或刷新其时间。

## 按月标题检索

检索只查所选月份的已归档标题及旧人工样刊的旁证标题，不搜索正文。提交后才读取本站固定路径`/world/search/YYYY-MM.json`，关键词留在浏览器内，不进入请求URL、请求体或后端搜索接口；检索不请求新闻源，也不下载全年标题集合。目录筛选的domain/type/language可以放入页面URL，与标题关键词无关。

关键词按空白分词，进行Unicode兼容规范化与大小写折叠；所有词都须命中同一条目的标题集合。不使用正则表达式执行读者输入。结果分批显示，每批50条，链接直达原报道，并提供归档日入口。

每月索引按UTF-8序列化后的大小设32 MiB上限；超过时不截取前若干标题冒充完整索引，而是将该月检索标为不可用，完整月历与日页继续保留。浏览器也检查响应类型、声明/实际读取大小与字段，不跟随索引重定向。切换搜索或离开页面会取消请求，已成功读到的月份只在本页内存缓存，销毁时清理。

无JavaScript时隐藏检索和动态筛选控件，读者仍可从月历逐日阅读完整标题。索引失败与超限都有按月浏览入口，不把网络错误写成「没有匹配结果」。

## 每周链接报告与季度复核

`.github/workflows/check-information-sources.yml`独立于采集和Pages工作流，设周一北京时间09:40及workflow_dispatch，时程仍可能受GitHub排队影响。权限为contents: read，checkout不保留凭据，任务上限10分钟，报告写入Step Summary，不自动提交、删除、禁用来源或触发Pages。

`scripts/check_information_sources.py`只读approved目录的官网、official_links、approved订阅及其首页/说明地址，去重后检查；collect=false的approved订阅也可被观察，但不会因此自动启用。站内`/marx/`、`/english/`不当作外站请求。明确目录HTTP官网可以保留HTTP，feed仍只允许HTTPS。

每跳重新核验URL及DNS返回的全部公网地址，再固定连接已核IP；不访问凭据URL、本机或私网，不忽略TLS证书。最多3次重定向，4线程；DNS、单次请求与单个目标分别受3秒、6秒、20秒上限保护。默认HEAD，仅405/501时回退Range GET，最多读1 KiB且丢弃，不解析网页或追踪文章。

报告将2xx、401/403/429受限、404/410、TLS错误、超时、DNS错误和安全拦截分开，403不自动称死链。普通网络失败只生成报告，CLI返回0；目录/输出配置错误会失败。每季度人工复核推荐理由、来源身份、订阅栏目、收费/登录和地区访问变化，必要时先停collect并写明原因；自动报告不能替代新的名单授权与人工审阅。

## 本地维护与检查

修改来源时只编辑新canonical文件及对应审核说明，保持目录与feeds字段一致，更新checked日期；不要把一次可用性测试变成「所有地区畅通」的承诺。新增来源或恢复采集先核实官方归属与订阅内容，再按获授权范围调整status/collect。

以下命令使用本地资料或模拟网络，不采集新闻、不读写远程存档：

```powershell
python scripts/test_world_sources.py
python scripts/test_world_archive.py
python scripts/test_world_pages.py
python scripts/test_information_source_links.py
python scripts/test_news_snapshot.py
python scripts/test_news_archive.py
python scripts/test_archive_collection.py
node scripts/test_world_ui.cjs
python scripts/build_site.py --site-url https://xieyuqing.me
python scripts/check_site.py --site-url https://xieyuqing.me
```

本地已有真实存档检出时，使用默认`.local-checks/news-archive`即可；也可先设置`$env:NEWS_ARCHIVE_PATH = '.local-checks/my-news-archive'`再构建。没有存档时应检查不可用文案，而非创建虚假历史数据。生成文件只写入构建输出目录，不直接编辑。

需要主动只读检查官网链接时，另运行下列命令；它会联网，但只生成ignored报告，不修改配置：

```powershell
python scripts/check_information_sources.py --output .local-checks/information-source-links/report.json --summaryMarkdown .local-checks/information-source-links/report.md
```

采集、capture本地合并与上线后一次性旧Release导入步骤见[今天页维护](今日简报维护.md)。`publish`入口是远程写入，仅供受信任main分支Actions使用，不列作普通本地检查。是否导入成功、存档是否被发布构建读取、链接周报是否按时运行，都以发布后的真实记录为准。
