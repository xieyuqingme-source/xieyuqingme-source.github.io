# 英文站与静态全文翻译

中文首页保留在 `/`，英文入口为 `/en/`；个人介绍、作品说明和文章目录分别为 `/en/about/`、`/en/projects/`、`/en/articles/`。导航里的 `EN` / `中文` 切换网站语言，英文文章目录内的筛选按钮区分中文译文与英文原创。没有浏览器语言强制跳转。摄影、地图、排行及外部独立工具继续使用现有界面，英文入口明确提示其中文界面或原项目使用方式。

原始中文 Markdown、网址和发表日期保留。译文为构建时读取的完整英文 Markdown，不调用在线翻译或付费服务。英文原创仍只有原来的 `/articles/English%20Articles/...html` 地址，使用英文阅读控件，不生成第二份译文。译文与英文原创只在英文目录中各出现一次；文章总数、中文/英文原创数量及 RSS 只统计原文，译文不重复计数。

## 新增与更新译文

- 每篇中文原文的译文放在 `blog/translations/en/<原中文文件名>.md`，以翻译后的 `# English title` 开头。正文为完整翻译，保留所有段落的含义、图片和链接目标、代码块与行内代码、表格、列表、引文和脚注。不要用摘要代替正文。
- 汇总记录在 `blog/translations/manifest.json`，格式为 `{"version":1,"translations":{"中文文章/<文件名>.md":{"file":"blog/translations/en/<文件名>.md","source_sha256":"<原文原始字节的 SHA256>","title":"English title","status":"complete","method":"AI-assisted translation"}}}`。`notes` 可选，用来保留必要的译注或原文疑点，不改写原文事实。
- `status: complete` 仅用于已经完成的全文；未完成可以不登记，或只登记 `{"status":"pending"}`。译文和 manifest 都属于公开源码，不能包含本机路径、密钥或私人笔记。
- 原文哈希不匹配时，目录显示译文待更新，并链接到中文原文；构建不发布过时译文。更新全文并核对后，再更新哈希。缺少文件、错配标题、被改变的图片/链接/代码/结构或不安全路径会使检查失败。
- 英文译文使用 `/en/articles/<原文件名去掉 .md>.html`。每页都有 `Original / 中文原文` 指向精确原文，双方有 reciprocal hreflang，且每页 canonical 指向自身。正文英文标题对应的章节保留原文 heading ID，因此原有片段链接与目录仍有效。
- 译文中的相对媒体链接始终以原中文 Markdown 的目录解析。译文评论的 `data-article-path` 和浏览/评论计数的 `data-stats-path` 继续使用原文路径，沿用历史 Waline 讨论，不能换成 `/en/` 路径。

检查命令（使用已准备好依赖的 Python）：

```powershell
python scripts/check_translations.py
python scripts/check_translations.py --require-complete
python scripts/test_english_site.py
node scripts/test_english_archive.cjs
node scripts/test_english_waline.mjs
python scripts/build_site.py --site-url https://xieyuqing.me
python scripts/check_site.py --site-url https://xieyuqing.me --require-complete-translations
```

普通检查允许真实存在的 pending/stale 状态；发布前要核对本次承诺的翻译范围，需要全部中文文章都有当前译文时使用 `--require-complete` 或 `--require-complete-translations`。这些检查不请求外部链接，也不代表已经部署。

英文首页与个人介绍模板在 `home/en/`；作品英文文案在 `home/en/projects.json`，只覆盖公开描述，链接与截图仍取自原 `home/projects.json`。修改中文个人资料或作品描述后，应同步核对英文文案。主构建只更新自有英文输出清单中登记的页面；过时译文会从生成目录移除，未知文件不会被递归删除。
