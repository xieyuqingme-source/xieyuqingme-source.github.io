# 雨聊英语角维护

更新于2026年10月29日。栏目面向中文读者，用词源故事、公版经典、语言对照与考据介绍英语，不要求每日手工更新。

## 页面与修改入口

| 页面或功能 | 地址 | 源文件 |
| --- | --- | --- |
| 栏目首页与筛选 | `/english/` | `english-corner/catalog.json`、`home/english-corner.template.html` |
| 知识卡片 | `/english/<slug>/` | `english-corner/cards/<slug>.md`及清单中的对应元数据 |
| 经典难词 | 每张经典的原文下方 | `english-corner/notes.json` |
| 中英数字转换器 | `/english/tools/numbers/` | `scripts/english_corner.py`的页面说明、`home/assets/english-numbers.js`的精确运算 |
| 英语名句 | `/today/`及`/en/today/`的每日阅读 | `home/brief/english-quotes.json`、`english-quotes-review.json`、`english-quotes-sources.md` |
| 栏目加载、校验、渲染 | 构建时使用 | `scripts/english_corner.py` |
| 名句加载、校验与初始卡片 | 构建时使用 | `scripts/daily_brief.py` |
| 筛选与样式 | 英语角页面 | `home/assets/english-corner.js`、`english-corner.css` |
| 名句轮换与样式 | 两种今天页 | `home/assets/daily-reading.js`、`home-daily.css` |
| 导航和页脚 | 全站 | `scripts/site_i18n.py`及`home/locales/common.json` |
| 关于本站的英语角说明 | `/about/#site`、`/en/about/#site` | `scripts/build_site.py`的`render_site_notes()` |

`catalog.json`是卡片的唯一发布清单，构建不会扫描私人笔记。需要借鉴个人资料时，应先整理成仓库内的公众稿，再回到公开版本核对；不把个人学习安排、真实同学姓名或本机路径带进源码。普通构建、页面阅读、筛选、换句和数字转换均不为本栏目请求外部资料；只有读者点击来源链接才前往原站。

英语角只生成中文版，不生成`/en/english/`，也不加入双语栏目映射`FEATURES`。英文站的导航写`English Corner (中文)`，仍指向`/english/`；英语角本身不显示EN切换。页面加入主sitemap，不计入原文章数量、RSS或文章翻译清单；首页保持五块。

## 卡片清单与正文

清单顶层必须恰有`version`、`columns`、`cards`，版本为1。四个栏目ID固定为`words`、`classics`、`between`、`myths`；每个栏目提供`id`、`title`、`english`、`description`。

每张卡片的共同必填字段：

| 字段 | 含义与约束 |
| --- | --- |
| `slug` | 2–64个小写英文字母、数字或连字符，以字母开头，唯一；`tools`保留给工具路径 |
| `column` | 上述四类之一 |
| `title`、`summary` | 公开纯文本，分别不超过120字符；summary是直接给答案的30秒版，不能写成截断摘要 |
| `level` | 整数1、2、3，分别为入门、进阶、挑战 |
| `tags` | 1–6个短标签，每个不超过24字符 |
| `sources` | 来源对象列表，字段恰为`label`、`url`、`checked_on`；每卡至少1项，考据至少2项，最多12项；核对日期为`YYYY-MM-DD` |
| `related` | 最多6个项目；填写另一张已发布卡片的slug，或以`/articles/`开头的实际原文章路径（如`/articles/文章名.html`），不填尚未生成的页面 |
| `added` | 加入日期，`YYYY-MM-DD` |
| `status` | `published`或`draft`；只有published生成页面。draft同样接受字段、正文与来源检查，不能拿它隐藏坏数据 |
| `ai_assisted` | 布尔值，如实说明初稿和例句是否有AI辅助；不能为省略说明而写false |

来源URL必须是安全的公开HTTPS地址，无凭据、私网地址、控制字符或本机路径。清单不接受未知字段。构建只读取清单明确列出的`cards/<slug>.md`；目录符号链接和指向仓库外的路径会被拒绝。

正文从H2开始，不另写H1；H1由清单标题生成。各类必需的小节都应有正文，同名小节不能重复，代码围栏里的假标题不算小节。

| 栏目 | 必需H2 | 专有元数据 |
| --- | --- | --- |
| 词的身世 | `故事`、`可以这样用` | 必填`headword`；可选`journey`，每站恰为`language`、`form`、`period`，不确定的时间留空，不编贸易路线 |
| 经典一页 | `导读`、`原文`、`可以这样用` | 必填下述`work` |
| 中英之间 | `对照`、`为什么`、`可以这样用` | 不填写其他类别的专有字段 |
| 考据 | `流行说法`、`证据`、`结论` | 必填`verdict`，值为真、假、存疑、部分正确 |

允许补充有内容的新H2，但不要删必需小节。Markdown使用markdown-it渲染，关闭原始HTML；第一版不放图片，引用只用公版原文。例句必须写明本站编写，不冒充原作；词的身世与中英之间建议300–700字，考据300–800字，经典导读200–400字。正文自然展开，不在卡片内裁切或滚动。

首页无脚本时按四类完整显示，栏目介绍链接跳到相应小标题；有脚本时支持栏目和难度筛选，写进`column`、`level`查询参数，并通过详情面包屑保留返回状态。不使用持久存储保存筛选，不添加联网搜索。

## 经典原文、公版与难词

`work`必填字段为`author_zh`、`author_en`、`title_zh`、`title_en`、`first_published`、`author_died`、`range`、`edition`、`edition_url`、`excerpt_words`、`excerpt_sha256_lf`。作者、作品、选段起止和具体版本分开记录；电子书上线日期不等于原作出版日期，创作日期也不等于出版日期。遇到版本节录本，应明确说明范围，不能称为原信全文。

按构建时北京时间年份Y检查：`first_published ≤ Y−96`且`author_died ≤ Y−51`；2026年的门槛分别为1930、1975。这是本栏目的保守筛选规则。只引用原作正文，不取现代编者导言、注释或受保护的现代译文；歌词一句不收。年份应有具体版本或可靠机构资料支持，不能仅填一个恰好过关的年份。

原文放在`## 原文`，不超过600个英文词。构建从解析后的该小节取得内容，把CRLF和单独CR换成LF，再去掉小节首尾空白；其余内部字符、标点、空格和换行均保留。`excerpt_sha256_lf`是这些UTF-8字节的SHA-256。计词使用`[A-Za-z]+(?:[’'-][A-Za-z]+)*`，与`split()`口径不同。修改原文后应回原版重新核对，再同步词数和指纹，不能只为让测试通过而重算。

可以在仓库根目录运行下列离线片段检查已有卡片的取值：

```python
import sys
from pathlib import Path
sys.path.insert(0, "scripts")
from english_corner import sections, text_hash, word_count

body = Path("english-corner/cards/keller-water.md").read_text(encoding="utf-8")
original = sections(body)["原文"]
print(word_count(original), text_hash(original))
```

`notes.json`格式为`{"version":1,"works":{"<slug>":[...]}}`。每篇经典必须有3–6项；每项字段为`term`、`meaning`、`source_url`、`source_label`、`checked_on`。term必须实际出现在该篇原文中，且同篇不能重复；meaning是结合上下文整理的中文含义，来源应是读过的公开词典。不要直接复制整段现代词典定义。

第一版把难词列在原文后的表格，不抽取文选的浮层组件。这个选择避免让文选注释和选择功能承担额外改动；将来需要浮层时再评估共享代码，不维护两套几乎相同的实现。当前代码使用现有的同一套浅色/深色主题，已没有需求草稿提到的两套可切换皮肤，故不恢复旧皮肤系统。

## 英语名句的三份资料

`english-quotes.json`顶层为`version:1`及`quotes`数组。每条共同字段：`id`、`text`、`translation`、`translation_source`、`author_zh`、`author_en`、`work_zh`、`work_en`、`locator_zh`、`first_published`、`author_died`、`url`、`note`；可选`related`须指向已发布的`/english/<slug>/`。未知字段、重复ID、忽略标点与大小写后重复的原句都会拒绝。

- 英文原句同时不超过45词和300字符，中文译文不超过120字符，知识说明note不超过160字符。
- 原句和公版日期规则同经典。来源链接指向实际原文，不把名言搜索页当出处。
- `translation_source:{"type":"site"}`会在引文说明中显示“中文为本站译文（AI辅助，逐句核对意思）”。
- 使用公版出版中译时，填写`{"type":"published","name":"译本及译者","url":"https://…","translator_died":年份}`；译者去世年也必须满足Y−51。还要人工核定所引译本本身的出版时间与可用范围，不能只靠译者卒年就复制后来出版的文字。现有schema没有单列译本出版年，字段检查不替代这一步；本批全部使用site类型。不得复制仍受保护的现代译本。
- 两种今天页读取完全相同的英文原句、中文译文、作者作品、说明和相关链接；只有标题、按钮及栏目入口文字跟随页面语言。正文分别用`lang="en"`、`lang="zh-CN"`标注。

`english-quotes-review.json`也使用`version:1`及`quotes`。每条必须有`id`、`text_sha256_lf`、`source_url`、`locator`、`checked_on`、`method`、`source_sha256_lf`、`misattribution_check`、`public_domain`，可选`bibliography_urls`。

其中`public_domain`恰含`first_published`、`author_died`、`basis`。每个展示ID要对应恰好一条核查记录，原句LF指纹、来源URL、出版与卒年必须一致。原句指纹不额外去掉首尾字符；不要套用经典小节的strip步骤。来源页指纹应从当次真正核对的源文件生成，并注明核查方法和定位。离线检查能发现正文与记录不一致，不能代替重新阅读原文，也不会联网证明远程页面未变。

`english-quotes-sources.md`是公开逐条通读索引，记录原句、译文、位置、语境、来源和翻译身份。修改名句后同步三份文件；新增数量与作者分布从当前数据统计，不在代码中硬编码每日句子。第一版120条，每位作者不超过12条，按作者交错排列；发表时间、人物台词与反讽语境都要留有依据。

两张阅读卡片分别有独立牌组和按钮。北京时间日期决定首句，先遍历完整池再洗牌，轮次交界不立即重复。60秒检查仅在跨日时重置，不覆盖读者手动选择；中英切换用一次性内存交接保留两套当前句和剩余顺序，普通离开后返回重新按日期开始。名句不使用localStorage或sessionStorage，离页时清理监听与计时器。无JavaScript时仍有构建当天的两张完整卡片，换句按钮隐藏。

## 数字工具与资源接入

数字转换用BigInt定点运算，保留4位输入小数；支持阿拉伯数字、正确三位分节的逗号/空格、全角数字和标点、数字加十百千万亿、按单位从大到小的复合写法，以及不区分大小写的thousand/million/billion/trillion和a million。第一版不识别纯汉字数词，不支持含义不统一的“兆”。

范围为0至小于10¹⁶。输出三位/四位分节、中文简写与整数读法、英文简写及小于10¹⁵整数的英文全拼。英文简写最多两位小数，发生近似时显示≈；四位分节明确为演示。现代英文全拼采用美式不加and，页面另说明英式习惯。无脚本时保留静态单位对照表。

三个新CSS/JS资源通过`english_corner.py`复制，由`version_shared_assets()`的资产名单及正则同时登记版本号，在模板中本地加载。页面脚本受现有PageScope包装，并登记离页清理。不要编辑`_site_unified/`的生成文件，也不要在运行时下载词典、Gutenberg正文、字体或CDN脚本。

## 新增、修改与退出的步骤

1. 先确认选题适合中文读者，读具体来源，核清事实与公版边界。无法确认的候选先退出，必要时以“存疑”说明有文献支持的分歧，不能用它掩盖完全没有来源。
2. 卡片先写公众版Markdown，再登记清单、来源、相关链接；经典同时补work和难词。名句先核原文与译意，再更新三件套。自编例句、本站译文和AI辅助必须如实标注。
3. 删卡片时，同步清理其他卡片的related、名句related及notes；不保留指向已退出页面的入口。改变slug会改变公开地址，应优先保留已有稳定slug。
4. 跑以下检查和整站构建。生成目录由构建器管理；退出路由后确认sitemap和生成页面清理结果，不手工篡改输出。
5. 内容与工程验证都通过后，站主再用GitHub Desktop审阅与提交；本轮开发过程不自动提交或部署。


发布前还要运行`.github/workflows/pages.yml`中的全部本地检查，不能只跑新增测试。`--publication`在生成结果上核对路由、sitemap、来源文件与中文版例外；不触发发布。浏览器另运行`node scripts/test_english_corner_browser.cjs`，使用本机Chrome和可用的Playwright依赖，拦截外部请求、固定测试时钟；覆盖五种宽度、当前浅/深主题、键盘筛选、独立换句、中英交接、跨日、无脚本及生命周期清理。浏览器环境和截图放忽略目录，不作为产品依赖。

每次改内容要重新读相关页面，不把哈希通过等同于事实正确。核查缓存和完整来源正文留在本机证据目录，公开仓库只保存本轮选定的短原文、必要元数据和公开来源索引。
