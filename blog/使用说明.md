# 网站使用说明

本仓库维护 [xieyuqing.me](https://xieyuqing.me/) 的整个个人网站和站内应用，对应远端为 `xieyuqingme-source/xieyuqingme-source.github.io`。日常维护使用这个仓库的源码目录；旧主页仓库及旧输出仅作历史对照，不作为当前发布来源。迁移过程见[单仓库迁移与回滚](单仓库迁移与回滚.md)，无需重复改名或切换远端。

## 网站入口与应用范围

| 入口 | 内容 | 维护依据 |
| --- | --- | --- |
| `/` | 个人主页、栏目入口、最近文章 | `home/index.template.html` |
| `/articles/` | 中文文章、英文写作、搜索筛选、RSS | 两个文章目录、`blog/` |
| `/projects/` | 站内应用和独立工具的作品展示 | `home/projects.json` |
| `/photos/` | 摄影相册与照片故事 | `photos/catalog.json`、`photos/images/` |
| `/map/` | 足迹地图、时间轴、访客制作与导出 | `map/catalog.json`、地图模板和脚本 |
| `/game/`、`/game/ranking/` | 小游戏入口与从夯到拉排行 | 游戏、排行模板和脚本 |
| `/about/` | 中英文个人介绍与联系方式 | `home/about.json`、关于页模板 |

足迹地图和排行工具的实现就在本仓库，均可在浏览器使用。地图草稿默认保留在当前页内存，主动保存后才写浏览器存储；排行将榜单与图片保存到当前浏览器的 IndexedDB。两者都提供文件导出供自行备份，不自动上传草稿或跨设备同步。操作与限制见[地图说明](足迹地图维护.md)和[小游戏与排行说明](../home/GAME_MAINTENANCE.md)。

作品页还展示雨聊公众号排版、Coze 论文速记工作流、雨聊壁纸三个独立仓库项目。本仓库只维护它们的展示资料与链接；源码、安装、运行及许可说明在各自仓库。公众号排版为本地工具，Coze 工作流需导入平台配置，壁纸为 Windows 测试版，不能把作品展示理解为本站已经托管所有工具。对应链接见[网站与作品维护](网站与作品维护.md)。

## 更新文章与个人资料

日常流程：写作 → 按原 SOP 整理到公开稿目录 → 本地构建与预览 → 审阅差异 → 用户决定提交、推送。

- 中文稿放在 `中文文章/`，英文稿放在 `English Articles/`；文章配图在 `images/`，补充资料在 `附属资料/`。
- 文章使用 `YYYY-MM-DD-标题.md` 文件名与 `# 标题`。更新旧文时保留文件名，以保持文章网址及评论标识稳定。
- 文章按原发表日期倒序排列。特殊日期依据存放在 `blog/publication-dates.json`，不会重新写入正文；年月精度照实显示，未知日期标为“发表时间待确认”，转载日期与首发日期分别说明。
- 文章栏目首页及中英文列表自动收录两个文章目录中的 Markdown。README 的 GitHub 文章索引仍按原 SOP 维护，构建不会替你更新该索引；相册、地图、作品和游戏不计入文章数量或 RSS。
- README 是仓库说明与文章索引，**不再生成“关于我”正文**。独立关于页使用 `home/about.json`，首页短简介在 `home/index.template.html` 中单独维护。旧 `/articles/about.html` 兼容跳转至 `/about/`。
- `blog/config.json` 管理文章站标题、描述、网址及文章栏目文案；`article_heading`、`article_description`、`article_english_description` 对应文章栏目，不作为全站功能清单。
- 保留用户确认的个人介绍、公众号名称“谢雨聊”和公开邮箱；不要猜测个人信息或补造公众号链接。
- 缺少图片、附件或站内文章链接时，构建会报错。支持 Obsidian 脚注和表格中的 `<br>` 换行；其他原始 HTML 按文字处理。网页链接转换不会改写 Markdown 源文件。

### 公众号排版

网站文章页已移除公众号复制、排版预览及专用脚本。需要公众号排版时使用独立的[雨聊公众号排版工具](https://github.com/xieyuqingme-source/yuliao-wechat-editor)，按其 README 在本地导入文章与图片、预览、复制或导出。该工具目前没有在线运行版。公众号后台的粘贴、图片保存和手机效果仍需实际核对；网站阅读页的显示效果不能代替工具或公众号后台验收。

## 构建、检查与本地预览

以下命令在仓库根目录运行，使用 Python 3.10+；运行 JavaScript 检查还需 Node.js。依赖版本以 `blog/requirements.txt` 为准，Pillow 需要 WebP 与 LittleCMS 支持。若本机同时安装多个 Python，请使用已经准备好依赖的同一个解释器执行安装和构建。

```powershell
python -m pip install -r blog/requirements.txt
python scripts/build_site.py --site-url https://xieyuqing.me
python scripts/check_site.py --site-url https://xieyuqing.me
python scripts/preview_site.py
```

`build_site.py` 统一生成全部栏目，内部复用 `build_blog.py`，并检查站内链接、锚点和发布元数据。`check_site.py` 可单独复核生成结果；它不访问网络，不能证明外部链接或线上部署已可用。使用正式根地址参数，不附加 `/articles/`、`/projects/` 等子路径。普通构建不重新导出相册，也不从私人时间表更新公开地图。

打开 <http://127.0.0.1:8767/>，各栏目使用同一端口和相同路径。服务仅监听本机，禁止列目录及隐藏路径；端口占用时运行 `python scripts/preview_site.py --port 8768`。终端按 `Ctrl+C` 停止。

`_site_unified/` 是当前统一生成结果，工作流只上传该目录；`.blog-deps/` 是可选本地依赖，`.local-checks/` 是本机检查记录，均被 Git 忽略。旧 `_site/` 不作为当前工作流输出，`_site_map_preview/` 仅供单独的地图草稿预览。不要直接修改生成 HTML。构建会更新自有输出并复用、清理已登记的派生图片，但保留已有的其他文件；删除或改名文章后可能留下旧 HTML，处理方式见[网站与作品维护](网站与作品维护.md)。

针对模板、生成器或交互修改，可按维护指南选择相关检查；仅调整说明时应优先核对 Markdown 链接、路径、命令和差异。常用检查为：

```powershell
python scripts/test_build_blog.py
python scripts/test_build_site.py
python scripts/test_about_routes.py
python scripts/test_game_routes.py
node scripts/test_waline_logic.mjs
python scripts/test_archive_pages.py
```

最后一项需要当前构建结果和 Node.js。相册、地图、排行等专项检查见各自文档；代码和模拟 DOM 检查不等于真实设备视觉验收。

## 阅读与互动

- 主题优先使用浏览器中保存的浅色或深色选择，否则跟随系统；没有检测能力时采用浅色。
- 文章栏目提供主题、年份筛选、标题与摘要搜索，每页 12 篇。切换筛选回到第一页；链接保留条件和页码。按 `/` 可进入搜索。
- 分页可输入页码后跳转；无效输入显示提示，只有一页或无结果时隐藏分页区。
- 阅读页有预计阅读时间、阅读进度、相邻文章及章节目录。桌面目录可放左侧、右侧或隐藏，手机使用展开入口；宽表格可横向滚动，图片适应屏幕。
- RSS 地址为 <https://xieyuqing.me/articles/feed.xml>，每次构建更新。
- `blog/site.js` 管理文章交互，`blog/style.css` 管理阅读样式；正文仍来自公开 Markdown。禁用 JavaScript 后仍可浏览正文和使用原生目录链接。

## 评论与浏览统计

本地 `blog/waline.json` 的 `enabled` 与 `backendVerified` 当前均为 `true`，使用独立的 Waline 服务。历史后端验证、配置示例及发布后验收记录见[Waline 接入说明](Waline接入说明.md)；本地开关不能证明当前线上版本已生效。

评论及统计会访问外部后端，不能将地图、排行的“本地处理”扩大为全站隐私承诺。当前集成的列表和本地预览只查询计数；正式站文章正常加载会发送浏览增量。评论展示方案保留 IP 属地，不公开完整 IP，隐藏浏览器与系统标签；后端仍保存 IP / UA，原始 UA 也可能通过公开接口返回。隐藏标签不等于不采集这些信息。不要把凭据、管理令牌或数据库连接写入仓库。

## 公开边界与发布

普通构建只读取仓库里的公开文章及相册、地图白名单，不扫描私人 Vault。只有显式的本机导出流程才读取选定的私人来源：

- 相册：`./scripts/preview_photos.ps1` 会读取本机配置、重新导出选定相册并构建预览，使用前先确认公开范围。见[摄影相册维护](摄影相册维护.md)。
- 地图：`./scripts/preview_map.ps1` 读取本机时间表，生成单独草稿预览，不改公开目录；发布白名单需要逐项明确批准。见[足迹地图维护](足迹地图维护.md)。

不要提交原始私人笔记、整个附件库、本机路径、来源映射、草稿 JSON、测试日志或密钥。`.photos-local.json`、`.map-local.json`、`.photo-cache/`、生成目录及检查记录保持忽略。公开稿中的原图、附件、照片故事及地图时间地点都应逐项审阅，不能仅凭“已去除 EXIF”判断适合公开。

本地构建、测试和预览不会触发发布。由用户在 GitHub Desktop 核对仓库、Changes 与差异，选择本次文件后 Commit、Push；推送 `main` 会触发已有的 `Publish personal site`，应等待 build、deploy 成功后再检查线上各栏目。不得从旧主页备份仓库发布日常修改。GitHub About 描述属于远端仓库元数据，修改 README 不会自动更新它。
